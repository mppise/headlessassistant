Prerequisites

Before embedding HeadlessAssistant you need:

  • The headless-assistant.js bundle hosted somewhere your page can reach (your CDN, same server, etc.).
  • An API endpoint that accepts POST { customer_id, message, history } JSON and returns either a full JSON response or an SSE stream. See the API contract for details.
  • A short-lived Bearer token for that endpoint.

No build tool, no package manager, and no framework are required on the host page.

Manual init (recommended) C01-F02

Use HeadlessAssistant.init(config) to mount the widget with a plain JavaScript object. This is the preferred approach because it lets you inject runtime values — such as the authenticated user's ID and display name — directly from the page context without a separate config file fetch.

Step 1 — Load the script

<script src="/path/to/headless-assistant.js"></script>

Step 2 — Call HeadlessAssistant.init()

HeadlessAssistant.init({ ai_endpoint: 'https://your-api.example.com/chat', bearer_token: 'your-short-lived-scoped-token', customer_id: 'CUST-00123', // authenticated user's account ID user_name: 'Sarah Johnson', // shown in greeting bubble max_turns: 10, stream_mode: 'sse', theme: { header_title: 'Billing Assistant', placeholder_text: 'Ask about invoices, payments, or coverage…', primary_color: '#CC0000' } });
If user_name is supplied and there is no prior conversation history, the widget greets the user by first name when the panel first opens (e.g., "Hi Sarah! How can I help you today?"). The greeting is not saved to history.
Calling init() while the widget is already mounted is a no-op (a warning is logged to the browser console). Call HeadlessAssistant.destroy() first if you need to re-mount with different config.

Auto-init (script tag) C01-F01

The simplest integration for static pages where runtime values are not needed. Add a <script> tag with a data-config attribute pointing to your JSON config file. The widget mounts automatically when the page loads.

Step 1 — Create your config file

Save this as headless-assistant.config.json on your server:

{ "ai_endpoint": "https://your-api.example.com/chat", "bearer_token": "your-short-lived-scoped-token", "max_turns": 10, "stream_mode": "sse", "theme": { "header_title": "My Assistant", "placeholder_text": "Ask me anything…", "primary_color": "#4F46E5" } }

Step 2 — Add the script tag

<script src="/path/to/headless-assistant.js" data-config="/path/to/headless-assistant.config.json"> </script>
Auto-init fetches the config file at runtime. customer_id and user_name cannot be set dynamically this way — use manual init when you need to pass authenticated user context.

Floating bubble mode C01-F05

This is the default mode. When no container is specified in the config, HeadlessAssistant renders a fixed-position chat bubble in the bottom-right corner of the page.

  • Clicking the bubble opens the chat panel.
  • The panel slides in with a smooth CSS transition.
  • Clicking the ✕ button in the panel header collapses it back to the bubble.

No extra HTML is needed on your page — the widget injects all its own DOM.

Inline embed mode C01-F06

Mount the widget inside a specific element on your page by providing a container CSS selector. The widget fills the container and is visible immediately — no bubble, no toggle button. Use this when you want the assistant to be a permanent, visible section of the page such as a dedicated support tab or sidebar panel.

Add a container element

<div id="my-assistant" style="width: 420px; height: 520px;"></div>

Pass the selector in your config

HeadlessAssistant.init({ ai_endpoint: 'https://your-api.example.com/chat', bearer_token: 'your-short-lived-scoped-token', container: '#my-assistant', // ← CSS selector stream_mode: 'sse' });
The container element must exist in the DOM at the time init() is called. If the selector matches nothing, a config error is displayed and the widget halts.

Config reference

All fields can be provided either in a JSON config file (auto-init) or as a plain JS object passed to init() (manual init).

Field Type Required Default Description
ai_endpointstring✅—Full URL of your chat API endpoint
bearer_tokenstring✅—Bearer token sent in the Authorization header on every request
customer_idstringauto UUIDAuthenticated customer identifier sent as customer_id in the request body. If omitted, an anonymous UUID is generated and persisted in localStorage
user_namestring—Display name shown in the greeting bubble on a fresh session. Only the first name is used (e.g., "Sarah M. Johnson" → "Hi Sarah!"). Omit to skip the greeting
containerstring—CSS selector for inline embed target. Omit for floating bubble mode. See Inline embed mode
max_turnsnumber10Max history turns sent to the API per request (1–100)
stream_mode"sse" | "json""sse"Whether to expect SSE streaming or a single full JSON response
response_fieldstring"message"Dot-notation path to the markdown content in the full JSON API response (e.g. "data.reply")

User identity

HeadlessAssistant sends a customer_id field with every API request so your backend can identify who is asking.

  • Authenticated users: pass customer_id in the init() call. The value is used as-is and is never written to localStorage.
  • Anonymous users: omit customer_id. The widget generates a crypto.randomUUID() on first load, persists it in localStorage under the key ha_user_id, and reuses it across sessions.
In a portal where the user is already authenticated, always supply customer_id explicitly. This avoids a mismatch between the anonymous UUID and your backend's account records, and eliminates a redundant localStorage write.

Clear history C01-F15

HeadlessAssistant stores conversation history in the browser's localStorage. Users can clear it in two ways:

  • Via the widget UI: click the trash icon in the widget header. This immediately wipes all stored conversation turns and resets the chat panel.
  • Programmatically: call HeadlessAssistant.clearHistory() from your page's JavaScript at any time.
// Example: clear history when the user logs out document.querySelector('#logout-btn').addEventListener('click', () => { HeadlessAssistant.clearHistory(); logoutUser(); });
Clearing history also resets the anonymous UUID stored in localStorage — a new UUID is generated immediately. If you supply customer_id in config, that value is unaffected — only the locally-generated UUID is reset.

Close / minimize C01-F16

Users can close the widget using the ✕ button in the header.

  • Floating bubble mode: the panel collapses and the chat bubble reappears.
  • Inline embed mode: the entire widget is hidden (display: none). To show it again, call HeadlessAssistant.destroy() and re-init, or manage visibility via CSS on the container element.

Destroy (SPA teardown)

In Single Page Applications (SPAs) where pages change without a full browser reload, call HeadlessAssistant.destroy() when the route that embeds the widget is unmounted. This removes all widget DOM nodes and event listeners cleanly.

// React example (cleanup in useEffect) useEffect(() => { HeadlessAssistant.init({ ai_endpoint: '...', bearer_token: '...' }); return () => { HeadlessAssistant.destroy(); }; }, []);
destroy() does not clear localStorage. Conversation history and any anonymous UUID are preserved until the user manually clears them or you call clearHistory().

Config errors C01-F22

If required fields are missing or invalid, the widget renders a visible error message and halts — it does not throw uncaught JavaScript exceptions.

Common causes:

  • ai_endpoint is missing or empty.
  • bearer_token is missing or empty.
  • The data-config URL returns a 404 or network error (auto-init only).
  • The container selector does not match any element in the DOM.

Check the browser console for details. The error message is displayed where the widget would have appeared.

Security notes

Your bearer token is visible in the browser. Anyone who can view your page source or network traffic can read it. Always use a short-lived, scoped token generated server-side — never your API master key.
  • Rotate tokens regularly and expire them quickly (minutes to hours, not days).
  • Scope the token so it can only call your chat endpoint — not admin or write endpoints.
  • HeadlessAssistant sanitizes all API response content before rendering to prevent XSS injection into your page.
  • Conversation history in localStorage is readable by any JavaScript running on the same domain. Do not send sensitive data through the widget if your portal runs untrusted third-party scripts.
